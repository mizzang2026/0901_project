결과물을 만들기 위한 핵심 정리

아래 순서만 이해하면 됩니다. 화면이 요청하고 → 서버가 처리하고 → DB가 저장합니다.

1. 한 줄 이해 2. 역할 구분 3. 작동 순서 4. 현재 상태 5. 할 일 6. 실습 전체 순서

1. 한 줄로 이해하기

GitHub에 코드를 보관하고, Vercel이 화면을 보여 주고, Edge Function이 요청을 처리하고, PostgreSQL이 데이터를 저장한다.

2. 무엇이 무슨 일을 하나?

서비스쉽게 말하면하는 일내가 할 일
GitHub코드 보관함화면·API·DB 설계 파일 저장변경한 코드를 올린다
Vercel웹사이트 전시장React 화면을 인터넷에 공개frontend를 연결하고 배포한다
Edge Function서버 직원로그인·게시글·댓글 요청 처리함수 코드를 따로 배포한다
PostgreSQL데이터 창고회원·게시글·댓글 실제 저장migration을 DB에 적용한다
Supabase Auth출입 확인회원가입·로그인·사용자 인증로그인 정보와 권한을 확인한다

중요: GitHub에 코드를 올렸다고 Edge Function과 DB까지 자동으로 바뀌는 것은 아닙니다.

3. 게시글을 볼 때 실제 작동 순서

  1. 사용자가 Vercel에 배포된 게시판을 연다.
  2. React가 /api/posts로 게시글을 요청한다.
  3. Edge Function이 요청을 받는다.
  4. Edge Function이 DB의 posts 테이블을 조회한다.
  5. DB가 게시글 데이터를 돌려준다.
  6. React가 받은 게시글을 화면에 표시한다.

실제 요청 주소

https://tbfekmfcbrecdkcaupeh.supabase.co/functions/v1/api/posts

4. 현재 프로젝트 상태

항목상태뜻
GitHub 코드확인 필요일부 변경 내용이 로컬에 남아 있음
Vercel 화면확인 필요VITE_API_URL 설정 확인 필요
Edge Function배포 완료API 서버는 올라가 있음
Supabase 연결정상DB 접속 가능
profiles있음회원 프로필 테이블 존재
posts없음게시글을 저장하거나 읽을 수 없음
게시글 API500 오류posts 테이블이 없어서 실패

지금 가장 먼저 해결할 문제: 기존 profiles는 보존하면서 빠진 posts와 관련 테이블을 DB에 추가해야 합니다.

5. 결과물에 필요한 DB 상자

  • profiles — 회원 프로필
  • admins — 관리자
  • posts — 게시글
  • comments — 댓글
  • post_reactions — 좋아요·싫어요
  • post_view_events — 게시글 조회 기록
  • notices — 공지사항
  • notice_view_events — 공지 조회 기록

6. 결과물을 완성하는 작업 순서

  1. DB 확인 — 현재 테이블과 데이터를 먼저 확인한다.
  2. DB 보완 — 기존 테이블과 충돌하지 않게 빠진 테이블을 추가한다.
  3. API 시험 — 게시글 조회가 200 응답과 JSON을 돌려주는지 확인한다.
  4. Vercel 설정 — VITE_API_URL이 정확한지 확인한다.
  5. 화면 시험 — 목록·작성·수정·삭제가 실제 DB와 연결되는지 확인한다.
  6. 최종 배포 — GitHub에 올리고 Vercel 배포 결과를 확인한다.

비밀값 주의: .env, .env.local, Service Role Key, Access Token, Vercel Token, 비밀번호는 GitHub와 frontend에 올리지 않습니다.

7. 오류가 나면 어디를 볼까?

오류먼저 확인할 곳
404요청 주소, React 경로, Vercel 배포 경로
401·403로그인 토큰, 사용자·관리자 권한
500Edge Function 로그, 환경 변수, DB 테이블·컬럼
화면이 이상함API의 실제 JSON과 React가 기대하는 데이터 모양

8. 실습으로 따라 하는 전체 순서

처음부터 다시 작업할 때는 아래의 GitHub → Vercel → Supabase → 연결 확인 순서로 진행합니다.

1단계 — GitHub 저장소 만들기

  1. GitHub에서 New repository를 누른다.
  2. 저장소 이름과 설명을 입력하고 공개 여부를 선택한다. 키나 특별한 설정값이 있다면 Private을 선택한다.
  3. Create repository를 눌러 저장소를 만든다.
  4. GitHub에 표시된 저장소 주소를 복사하고, 프로젝트 폴더에서 아래 명령을 차례로 실행한다.
git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin 저장소_주소
git push -u origin main

.gitignore는 GitHub에 올리지 않을 파일을 지정합니다. 특히 .env, .env.local, 비밀번호, 토큰, 비밀키는 절대 커밋하지 않습니다.

2단계 — Vercel에 프론트엔드 배포하기

  1. Vercel에 GitHub 계정으로 가입하거나 로그인한다.
  2. Add New → Project에서 GitHub 저장소를 Import한다.
  3. Root Directory를 frontend로 지정한다.
  4. Framework는 Vite, Build Command는 npm run build, Output Directory는 dist인지 확인한다.
  5. Deploy 후 Build Log와 실제 화면을 확인한다.
  6. Settings의 환경 변수에 공개 가능한 프론트엔드 설정만 등록하고 다시 배포한다.
VITE_API_URL=https://프로젝트-ref.supabase.co/functions/v1

Vercel Access Token이 필요하면 계정의 Settings → Tokens에서 만들고 로컬 .env에만 보관합니다. 토큰은 생성 직후 한 번만 보일 수 있으므로 안전한 곳에 보관합니다.

3단계 — Supabase 프로젝트 만들기

  1. Supabase에 GitHub 계정으로 가입하거나 로그인한다.
  2. Organization을 만들고 New project를 선택한다.
  3. 프로젝트 이름과 Database Password를 정하고, 가까운 Region(예: Seoul)을 선택한다.
  4. 프로젝트가 만들어지면 Project URL과 API 키를 확인한다.
  5. 백엔드 코드를 Supabase 방식의 Edge Function으로 배포한다.
  6. migration 파일을 DB에 적용해 필요한 테이블을 만든다.

4단계 — 키와 환경 변수 구분하기

값용도보관 위치
SUPABASE_URLSupabase 프로젝트 주소백엔드 환경 변수
SUPABASE_ANON_KEY브라우저용 공개 키(RLS 전제)필요한 경우 프론트엔드
SUPABASE_SERVICE_ROLE_KEY관리 권한이 있는 비밀키백엔드에만 보관
SUPABASE_ACCESS_TOKENCLI가 프로젝트에 접근할 때 사용로컬 환경 변수에만 보관
VERCEL_ACCESS_TOKENVercel CLI·자동화 인증로컬 환경 변수에만 보관

Vercel Access Token 찾아가는 순서

  1. Vercel 화면의 오른쪽 위 프로필 아이콘을 누른다.
  2. Account Settings로 들어간다.
  3. 왼쪽 메뉴에서 Tokens를 선택한다.
  4. 토큰 이름을 입력하고 유효기간을 정한 뒤 Create를 누른다.
  5. 생성된 값을 즉시 복사해 로컬 .env의 VERCEL_ACCESS_TOKEN= 뒤에 붙여 넣는다.

새로고침하거나 창을 닫으면 토큰 값이 다시 보이지 않을 수 있으므로 생성 직후 복사합니다.

Supabase Project URL과 API 키 찾아가는 순서

  1. Supabase Dashboard에서 사용할 프로젝트를 연다.
  2. 왼쪽 아래 Project Settings(톱니바퀴)를 누른다.
  3. API 메뉴를 연다.
  4. Project URL을 복사해 SUPABASE_URL= 뒤에 붙여 넣는다.
  5. Project API keys에서 anon/public 키를 복사해 SUPABASE_ANON_KEY= 뒤에 붙여 넣는다.
  6. service_role 키는 필요한 백엔드 환경에만 SUPABASE_SERVICE_ROLE_KEY=로 저장한다.

Supabase Access Token 찾아가는 순서

  1. Supabase 화면의 오른쪽 위 프로필 아이콘을 누른다.
  2. Account를 열고 왼쪽 메뉴에서 Access Tokens를 선택한다.
  3. Generate new token을 누른다.
  4. 토큰 이름과 유효기간을 정하고, 사용할 프로젝트와 필요한 권한을 선택한다.
  5. 설정을 검토해 토큰을 만든 뒤 즉시 복사한다.
  6. 로컬 .env의 SUPABASE_ACCESS_TOKEN= 뒤에 붙여 넣는다.

주의: Service Role Key와 Access Token은 공개 키가 아닙니다. GitHub 또는 브라우저에서 실행되는 frontend 코드에 넣지 않습니다.

5단계 — Supabase CLI로 연결하고 반영하기

cd backend
npx supabase link --project-ref 프로젝트-ref
npx supabase db push
npx supabase functions deploy api

migration은 DB 변경 이력을 순서대로 남기는 설계 파일입니다. 파일을 만든 것만으로 원격 DB가 바뀌지는 않으며, db push로 적용해야 합니다.

6단계 — 마지막 연결 확인

  1. GitHub에서 최신 코드와 .gitignore를 확인한다.
  2. Vercel의 Domain으로 접속해 화면이 열리는지 확인한다.
  3. Vercel의 VITE_API_URL이 Edge Function 주소와 맞는지 확인한다.
  4. Edge Function API가 정상 응답하는지 확인한다.
  5. Supabase Table Editor에서 데이터가 실제로 저장되는지 확인한다.

기억할 순서: 코드는 GitHub에 보관 → 화면은 Vercel에 배포 → 서버는 Edge Function에 배포 → DB는 migration으로 반영 → 환경 변수로 서로 연결

핵심으로 이것만 기억하기

화면에 오류가 보여도 화면만 고치지 않는다.

화면 → 요청 주소 → Edge Function → DB 순서로 확인한다.
