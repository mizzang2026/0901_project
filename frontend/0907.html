01

개발 환경 준비하기

새 컴퓨터에서 웹 개발을 시작할 때 따라가기 편한 순서입니다. 반드시 이 순서로 설치해야 하는 것은 아닙니다.

  1. VS Code 설치 — 프로젝트 파일을 열고 코드를 편집하는 도구.
  2. Node.js 설치 — 자바스크립트 실행 환경. 패키지 관리 도구인 npm도 함께 설치됩니다.
  3. Git 설치 — 코드 변경 기록을 관리하는 도구.
  4. GitHub 계정 만들기 — Git 저장소를 온라인에 보관하고 공유하는 서비스.
  5. Codex 준비 — 사용할 앱이나 확장 등 이용 형태에 맞춰 설치하고 로그인합니다.
  6. 프로젝트 폴더 열기 — 새로 만들거나 기존 저장소를 내려받아 개발을 시작합니다.

HTML·CSS·JavaScript 파일만으로 된 정적 페이지는 Node.js 없이도 만들고 열어볼 수 있습니다. Node.js는 npm이나 개발 서버 등 프로젝트에 필요한 도구를 사용할 때 준비합니다.

02

Git과 GitHub 구분하기

Git

내 컴퓨터에서 코드의 변경 기록을 관리합니다. 커밋은 선택한 변경 사항을 기록하는 작업입니다.

GitHub

Git 저장소를 온라인에 보관합니다. 다른 사람과 공유하거나 다른 컴퓨터에서 이어서 작업할 수 있습니다.

저장소(repository)는 프로젝트 파일과 Git 변경 기록을 관리하는 단위입니다. 내 컴퓨터의 저장소는 로컬 저장소, GitHub 등에 있는 저장소는 원격 저장소라고 부릅니다.

03

git config — 작성자 정보 설정

커밋에 기록할 이름과 이메일을 설정합니다. 아래 예시의 이름과 이메일은 내 정보로 바꿉니다.

git config --global user.name "내 이름"
git config --global user.email "내 이메일"

--global은 현재 컴퓨터 사용자 계정의 기본 설정입니다. 특정 프로젝트에만 적용하려면 그 프로젝트 폴더에서 --global을 빼고 실행합니다.

git config user.name
git config user.email
git config --list

이름과 이메일은 커밋 작성자 정보입니다. GitHub 로그인이나 업로드 권한은 별도로 인증해야 합니다.

04

프로젝트 시작하기

기존 저장소가 있으면 git clone

git clon이 아니라 git clone. 다른 사람의 프로젝트뿐 아니라 내 프로젝트도 코드와 변경 기록을 함께 내려받습니다.

git clone https://github.com/사용자명/저장소명.git
cd 저장소명

주소는 실제 저장소 주소로 바꿉니다. 현재 위치에 저장소 폴더가 만들어집니다. 비공개 저장소는 접근 권한이 필요하고, 로컬에서 수정하는 것만으로 원격 원본이 바뀌지는 않습니다.

새 프로젝트라면 git init

새 프로젝트 폴더에서 Git 관리를 시작합니다. clone으로 내려받은 프로젝트는 이미 Git 저장소이므로 다시 초기화할 필요가 없습니다.

git init
05

변경 확인 → 기록 → 업로드

git status변경 파일과 커밋 준비 상태 확인
git diff아직 스테이징하지 않은, 추적 중인 파일의 변경 내용 확인
git add .현재 폴더와 하위 폴더의 변경 사항을 커밋 대상으로 선택
git diff --staged커밋에 포함할 변경 내용 확인
git commit -m "변경 내용 설명"선택한 변경 사항을 로컬 기록으로 저장
git push원격 연결과 추적 설정이 된 브랜치의 커밋 업로드
git pull원격 변경 사항을 가져와 현재 브랜치에 통합

git diff에는 새로 만든 미추적 파일의 내용이 표시되지 않으므로 git status와 파일 내용도 함께 확인합니다. git pull은 다른 곳에서 작업한 내용을 받을 때 사용하며 충돌이 생기면 해결해야 합니다.

새 저장소를 GitHub에 처음 올릴 때

GitHub에 README 등을 추가하지 않은 빈 저장소를 만든 뒤, git init을 마친 프로젝트 폴더에서 실행합니다. 이미 clone한 저장소는 보통 origin이 연결되어 있습니다.

git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/사용자명/저장소명.git
git push -u origin main

origin은 원격 저장소의 별명이고, -u는 이후 간단히 git push할 수 있도록 추적 관계를 설정합니다. 업로드에는 인증과 쓰기 권한이 필요합니다.

실제 비밀번호나 API 키가 들어 있는 .env 파일은 git add 전에 .gitignore에 등록합니다. 이미 Git이 추적 중인 파일은 .gitignore에 적는 것만으로 제외되지 않습니다.

06

샌드박스 승인 메시지 이해하기

“Git 설정 파일 변경이 차단되었습니다. GitHub 로그인 정보를 Git 업로드에 연결하도록 허용하시겠어요?”

샌드박스는 도구가 접근하거나 변경할 수 있는 범위를 제한합니다. 이 메시지는 Git 인증 관련 설정 변경이 그 범위에서 차단되어 허용을 요청한다는 뜻입니다.

설정 변경을 허용하는 것 자체가 코드 업로드는 아닙니다. 정확히 어느 파일의 어떤 설정을 바꾸는지는 함께 표시된 명령어를 확인해야 합니다. 이 문구만으로 구체적인 변경 내용을 단정할 수는 없습니다.

07

필요한 기능 연결하고 배포하기

Supabase

데이터베이스나 회원가입·로그인 같은 기능을 붙일 때 사용하는 서비스입니다. 오늘 헷갈렸던 철자는 Superbase가 아니라 Supabase!

Vercel

웹 프로젝트를 배포해 다른 사람도 접속할 수 있는 주소로 공개할 때 사용하는 서비스입니다.

프로젝트를 만들고 확인한 뒤 GitHub에 저장하고, 필요하면 Supabase를 연결하고 Vercel로 배포합니다. 단순한 학습일지에는 데이터베이스가 필수는 아닙니다.

오늘은 각 서비스의 역할과 작업 흐름을 배웠습니다. 이 기록은 실제 연결이나 배포가 완료되었다는 뜻은 아닙니다.
