01

Git과 GitHub의 역할

Git

내 컴퓨터에서 파일의 변경 내용을 기록하고 관리하는 도구입니다. 언제 무엇을 바꿨는지 커밋 단위로 남길 수 있습니다.

GitHub

Git으로 관리하는 프로젝트를 온라인에 보관하고 공유하는 서비스입니다. 로컬의 커밋을 push하면 원격 저장소에 올라갑니다.

GitHub 저장소에 파일을 올리는 것과 웹사이트를 공개하는 것은 서로 다른 작업입니다. 웹사이트 공개에는 GitHub Pages 설정이 추가로 필요합니다.

02

VS Code의 Git 상태 표시

파일 탐색기 옆의 문자는 Git이 감지한 현재 상태를 뜻합니다.

U · Untracked새로 만든 파일이며 Git이 아직 추적하지 않는 상태
M · Modified이미 추적 중인 파일을 수정하고 저장한 상태
A · Added새 파일을 Git의 다음 커밋 대상으로 추가한 상태
표시 없음현재 커밋과 비교해 저장된 변경 사항이 없는 상태

M이 탐색기에 보이지 않더라도 git status나 VS Code의 소스 제어 화면에서 변경 여부를 확인할 수 있습니다. 파일을 저장하지 않았다면 Git은 아직 변경을 감지하지 못합니다.

03

Git 작성자 정보 처음 설정하기

Git을 처음 설치한 컴퓨터에서는 커밋에 남길 작성자 이름과 이메일을 한 번 설정해야 합니다. 이 정보는 GitHub 로그인 정보가 아니라 커밋 기록에 표시되는 작성자 정보입니다.

git config --global user.name "사용자 이름"
git config --global user.email "user@example.com"

--global은 이 컴퓨터에서 만드는 모든 Git 프로젝트에 기본값으로 적용한다는 뜻입니다. 설정이 잘 저장됐는지는 다음처럼 확인합니다.

git config --global user.name
git config --global user.email
git config --global --list

페이지에는 실제 이름과 이메일을 기록하지 않습니다. 공개 저장소의 커밋 정보도 다른 사람이 볼 수 있으므로, 이메일 공개가 부담스럽다면 GitHub에서 제공하는 비공개용 noreply 이메일을 사용할 수 있습니다.

04

GitHub 로그인과 인증 코드 입력

처음 git push할 때는 이 컴퓨터가 GitHub 계정에 접근해도 되는지 인증하는 과정이 나타날 수 있습니다. 비밀번호를 명령창에 직접 입력하는 대신 브라우저를 이용해 안전하게 승인합니다.

git push 실행→브라우저 로그인→일회용 코드 입력→접근 승인
  1. 터미널에서 git push를 실행합니다.
  2. GitHub 로그인 안내와 일회용 인증 코드가 나타나면 코드를 복사합니다.
  3. 안내에 따라 브라우저를 열고 GitHub 계정으로 로그인합니다. Google 계정으로 가입했다면 해당 로그인 방식을 사용할 수 있습니다.
  4. 브라우저의 인증 화면에 복사한 코드를 입력하고 접근을 승인합니다.
  5. 터미널로 돌아오면 인증이 완료되고 push가 계속 진행됩니다.

승인 후에는 Windows의 자격 증명 관리 도구가 인증 정보를 보관하므로 매번 같은 절차를 반복하지 않는 경우가 많습니다. 로그아웃, 자격 증명 삭제, 권한 만료 등이 발생하면 다시 인증할 수 있습니다.

인증 코드는 일회용이며 다른 사람에게 알려주거나 화면 캡처에 남기지 않습니다. GitHub 비밀번호, 액세스 토큰, 복구 코드도 프로젝트 파일이나 공개 페이지에 저장하면 안 됩니다.

05

프로젝트 전체를 GitHub에 올리는 순서

파일 작성→변경 확인→커밋→GitHub push 
git init
git add .
git commit -m "Add project files"
git branch -M main
git remote add origin https://github.com/사용자명/저장소명.git
git push -u origin main
git init
현재 폴더에서 Git 관리를 시작
git add .
현재 폴더의 변경 파일 전체를 커밋 대상으로 선택
git commit
선택한 변경 내용을 하나의 기록으로 저장
git push
로컬 커밋을 GitHub 원격 저장소로 전송

git add README.md는 README 파일만 추가합니다. 프로젝트 파일 전체를 올리려면 내용을 확인한 후 git add . 또는 git add --all을 사용합니다.

06

Live Server와 실제 웹 배포

Live Server

내 컴퓨터에서 작업 중인 HTML을 브라우저로 확인하는 로컬 미리보기 도구입니다. 기본적으로 인터넷에 공개되는 사이트는 아닙니다.

GitHub Pages

GitHub 저장소의 HTML·CSS·JavaScript 파일을 인터넷에 공개해 실제 웹 주소로 보여주는 정적 웹 호스팅 서비스입니다.

예전에 FTP로 웹서버에 파일을 올렸다면, 지금은 GitHub에 push하고 GitHub Pages가 그 파일을 웹사이트로 제공하는 방식으로 이해할 수 있습니다.

07

GitHub Pages 활성화하기

  1. GitHub에서 프로젝트 저장소를 엽니다.
  2. Settings → Pages로 이동합니다.
  3. Source에서 Deploy from a branch를 선택합니다.
  4. 브랜치는 main, 폴더는 /(root)를 선택하고 저장합니다.
  5. 배포가 끝나면 제공된 주소로 접속해 결과를 확인합니다.

현재 프로젝트의 저장소 주소와 Pages 예상 주소는 다음과 같습니다.

저장소
https://github.com/mizzang2026/0901_project

웹사이트
https://mizzang2026.github.io/0901_project/frontend/

첫 화면 파일이 frontend/index.html에 있으므로 주소 끝에 /frontend/가 붙습니다. 사이트 파일을 저장소 최상위로 옮기면 더 짧은 기본 주소를 사용할 수 있습니다.

08

무료 호스팅의 범위

GitHub Pages는 공개 저장소의 정적 웹사이트를 무료로 제공하기 때문에 개인 홈페이지, 수업 과제, 포트폴리오, 프로젝트 소개 사이트에 잘 맞습니다.

가능한 것

HTML, CSS, 브라우저에서 실행되는 JavaScript, 이미지와 같은 정적 파일을 웹사이트로 공개할 수 있습니다.

별도 서버가 필요한 것

PHP·Node.js 같은 서버 프로그램, 데이터베이스, 로그인 처리, 결제 기능은 별도의 백엔드 서비스가 필요합니다.

기본 github.io 주소는 무료입니다. 직접 구매한 도메인도 연결할 수 있지만 도메인 구입과 갱신 비용은 별도입니다.

09

수정 후 다시 공개하는 방법

사이트를 수정한 뒤 저장하고 아래 과정을 반복하면 GitHub와 Pages 사이트에 새 내용이 반영됩니다.

git status
git add .
git commit -m "Update website"
git push

git status로 올릴 파일을 먼저 확인하는 습관이 중요합니다. 비밀번호, API 키, 개인정보가 담긴 파일은 GitHub에 올리지 않습니다.
