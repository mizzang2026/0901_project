# 구현 가이드

## 1. 파일별 역할

### `frontend/index.html`

- 페이지 콘텐츠와 시맨틱 구조를 담당한다.
- CSS와 JavaScript 파일을 연결한다.
- 각 섹션에 내비게이션용 고유 `id`를 지정한다.

### `frontend/css/style.css`

- 색상, 글꼴, 여백 등 공통 디자인 토큰을 정의한다.
- 모바일 기본 스타일을 먼저 작성한다.
- 미디어 쿼리로 태블릿과 데스크톱 레이아웃을 확장한다.
- hover, focus, 모션 감소 상태를 포함한다.

### `frontend/js/main.js`

- 모바일 메뉴를 제어한다.
- 현재 연도를 표시한다.
- 테마 전환, 메뉴 강조, 폼 검증 등 선택 기능을 담당한다.
- HTML의 인라인 이벤트 속성 대신 이벤트 리스너를 사용한다.

## 2. 권장 구현 순서

1. 실제 프로필 콘텐츠와 링크를 준비한다.
2. `index.html`에 헤더와 모든 섹션의 구조를 작성한다.
3. CSS 변수와 공통 스타일을 정의한다.
4. 모바일 레이아웃을 완성한다.
5. 미디어 쿼리로 큰 화면 레이아웃을 작성한다.
6. 필수 JavaScript 기능을 구현한다.
7. 접근성, 링크, 반응형 화면과 콘솔 오류를 점검한다.
8. 이미지 최적화와 메타데이터를 마무리한다.

## 3. HTML 구조 예시

```html
<body>
  <header>...</header>
  <main>
    <section id="about">...</section>
    <section id="skills">...</section>
    <section id="projects">...</section>
    <section id="experience">...</section>
    <section id="contact">...</section>
  </main>
  <footer>...</footer>
  <script src="./js/main.js" defer></script>
</body>
```

## 4. 메타데이터

문서 제목, 설명, 문자 인코딩, viewport를 기본으로 설정한다. 공유 미리보기가 필요하면 Open Graph 제목, 설명, 이미지도 추가한다.

## 5. 완료 점검표

- [ ] 모든 섹션에 실제 또는 명확한 임시 콘텐츠가 있다.
- [ ] 내비게이션 링크가 올바른 섹션으로 이동한다.
- [ ] 모바일 메뉴가 키보드와 터치로 동작한다.
- [ ] 모바일, 태블릿, 데스크톱에서 가로 스크롤이 생기지 않는다.
- [ ] 이미지의 대체 텍스트가 적절하다.
- [ ] 모든 링크가 유효하고 외부 링크가 새 창에서 안전하게 열린다.
- [ ] 버튼과 링크의 focus 상태가 보인다.
- [ ] 브라우저 콘솔에 오류가 없다.
- [ ] 페이지 제목과 설명이 설정되어 있다.
- [ ] Lighthouse의 접근성, 성능, 권장사항 항목을 점검했다.

## 6. 범위 구분

현재 프론트엔드만으로 가능한 범위는 화면 표시, 인터랙션, 클라이언트 입력 검증까지다. 연락 폼의 실제 메시지 저장·메일 발송, 관리자 기능, 방문 통계 저장은 백엔드 또는 외부 서비스가 추가로 필요하다.
