PageSnap, 크롬 확장에서 Windows 캡처 도구까지

캡처 기능을 문서로 정의하고 Chrome 확장프로그램으로 구현한 뒤, Electron으로 데스크톱 앱을 만들었습니다. 실제 사용 중 발견한 고정 메뉴 반복, 영역 선택 오류, 복잡한 UI를 차례로 개선했습니다.

당일 Codex 대화의 실제 질문과 작업 결과를 바탕으로 정리했습니다. 인용문은 당시 질문이며, 테스트 수와 생성 결과는 당시 기록 기준입니다.

1. 기능부터 문서로 정리하기

실제로 입력한 질문

해당내용은 먼저 문서폴더에 기능별 문서 정리해서 md 화일로 만들어줘.

작업 프로젝트는 1026_1입니다. 처음에는 프론트·문서 폴더를 만들고, 이후 영문 이름인 frontend와 docs로 변경했습니다. 프로젝트 개요, 전체 화면과 단축키, 드래그 영역, 자동 스크롤, PNG·PDF 저장, 공통 화면과 예외 처리를 문서로 나눴습니다.

이 단계의 “전체 화면”은 모니터 전체가 아니라 현재 탭에서 보이는 웹페이지 영역, “1페이지”는 현재 화면 높이로 정의했습니다. 뒤에 Windows 앱으로 범위를 넓힐 때 이 정의를 다시 확인하게 됩니다.

2. Markdown 문서는 실행 파일이 아니다

실제로 입력한 질문

markdown 문서가 뭐야

.md는 Markdown 문서 파일입니다. # 제목, - 목록, **강조**처럼 간단한 기호로 내용을 정리합니다. 기능을 설명한 문서만으로는 캡처 프로그램이 실행되지 않습니다.

VS Code에서 문서를 열고 Ctrl + Shift + V로 미리보기를 확인했습니다. 문서를 검토한 다음 “문서를 기반으로 개발해서 파일을 만들어줘”라고 요청해 구현 단계로 넘어갔습니다.

3. Chrome 확장프로그램 구현과 설치

실제로 입력한 질문

문서를 기반으로 개발해서 파일을 만들어줘.

Manifest V3 기반 PageSnap에 현재 화면 촬영, Alt+Shift+S 단축키, 드래그 영역 촬영, 최대 20화면 자동 스크롤, 결과 미리보기와 PNG·PDF 저장을 구현했습니다.

manifest.json은 확장의 이름·버전·권한·실행 코드·단축키를 Chrome에 알려주는 설정 파일입니다. 직접 실행하는 파일이 아닙니다.

  1. Chrome에서 chrome://extensions를 엽니다.
  2. 개발자 모드를 켜고 “압축해제된 확장 프로그램을 로드합니다”를 선택합니다.
  3. 1026_1/frontend 폴더를 등록합니다.
  4. 일반 웹사이트에서 PageSnap으로 촬영하고 저장을 확인합니다.

Chrome 내부 설정 화면에서는 촬영할 수 없습니다. 당시 자동 테스트 8개와 브라우저 검증 6개가 통과했지만, 실제 설치 상태의 권한·단축키·다운로드 확인은 별도로 남겨 두었습니다.

4. 스크롤 캡처에 상단 메뉴가 반복되는 문제

실제로 입력한 질문

자동스크롤 캡쳐시... 상단 고정 메뉴가 계속 캡쳐가 같이 되는데... 상단 메뉴는 제외하고 캡쳐하도록 해줘

고정 메뉴는 스크롤을 내려도 화면 위에 계속 남아 있어서 촬영 이미지마다 반복되었습니다. 첫 화면에는 포함하고, 두 번째 화면부터 숨기는 방식으로 수정했습니다.

촬영 완료·중지·오류 후에는 숨긴 메뉴를 복원하도록 처리하고 해당 상황을 테스트했습니다. 확장 코드를 바꾸면 확장프로그램을 새로고침하고, 촬영할 웹페이지도 새로고침해야 수정된 동작을 확인할 수 있습니다.

5. Electron으로 데스크톱 앱 만들기

실제로 입력한 질문

기존 Chrome 확장 프로그램(Manifest V3)은 유지하면서, Electron을 활용해 Windows, macOS, Linux에서 실행 가능한 설치형 프로그램도 만들어 주세요. 기존 기능과 UI를 최대한 재사용하고, OS별 호환성을 고려해 구현해 주세요.

웹 기술로 만든 화면을 Electron의 데스크톱 창에서 사용하도록 확장했습니다. npm 접근 제한으로 도구 다운로드가 막혔고, 사용자가 설치를 마친 뒤 Windows 실행 파일을 만들었습니다.

cd C:\Users\User\Desktop\1026_1
npm.cmd install
npm.cmd start

start-desktop.cmd 실행 방법도 안내했습니다. 이 날 실제로 생성한 결과는 Windows용 폴더형 실행 파일입니다. 처음 요청한 macOS·Linux용 설치 파일까지 완성·검증한 것으로 기록하지 않습니다.

코드를 작성한 상태, 의존성을 설치한 상태, 실행 파일을 만든 상태, 실제 OS에서 동작을 확인한 상태는 각각 구분해야 합니다.

6. 웹페이지 캡처에서 OS 화면 캡처로 범위 수정

실제로 입력한 질문

윈도우용 화일은.. 꼭 인터넷 화면만을 캡쳐하는 기능은 아니고 윈도우에서 모든 다양한 화면을 캡쳐할 수 있어야 하는 프로그램을 만드는거였는데?

데스크톱 앱의 요구사항을 다시 잡았습니다. 바탕화면과 다른 프로그램을 포함한 모니터 전체 촬영, 드래그 영역 촬영, 메모장·탐색기 같은 프로그램 창 선택 촬영을 추가했습니다. 전체 화면은 Alt+Shift+S, 영역은 Alt+Shift+A로 실행하도록 했습니다.

이어 영역 선택 창에서 ERR_FAILED (-2)와 overlay.html 로딩 오류가 발생했습니다. 창의 로딩 방식과 초기화 순서를 수정해 1.0.1을 만들었습니다. 당시 자동 테스트 29개와 브라우저 검증 15개는 통과했지만 실제 Windows 영역 촬영은 재확인이 필요했습니다.

일반 프로그램의 자동 스크롤 촬영은 지원하지 않는 상태였습니다. 웹페이지 자동 스크롤 기능과 OS 캡처 기능의 범위를 구분해 기억해야 합니다.

7. 실제 사용에 맞게 작은 캡처 도구창으로 바꾸기

실제로 입력한 질문

앱 형태가 아니고 확장프로그램같은 ui인거야? 알캡쳐 같은 윈도우 전용 프로그램으로 만들어줘야 하는거 같은데? 윈도우 화면, 인터넷 화면.. 뭐 이렇게 나눠져서 한꺼번에 들어가있으니 사용하기가 너무 불편한데..

최종적으로 영역 캡처 · 전체 화면 · 창 캡처 세 버튼을 중심으로 작은 도구창을 만들었습니다. 인터넷·바탕화면·다른 프로그램을 같은 흐름으로 촬영하고, 웹페이지 자동 스크롤은 “더보기”의 별도 도구로 옮겼습니다. 트레이와 전역 단축키도 지원하도록 했습니다.

이 날 마지막 결과는 dist/1.1.0/win-unpacked/PageSnap.exe입니다. 폴더형이므로 주변 파일을 함께 유지해야 합니다. UI·로직 검증은 통과했으며, 실제 Windows 촬영·트레이 동작은 추가 확인 대상으로 남았습니다.

다시 기억할 핵심

요구사항 문서 → Chrome 확장 구현 → 설치·캡처 확인 → 고정 메뉴 처리 → Electron 확장 → OS 화면 캡처 → 오류 수정 → 작은 도구창 UI 개선

캡처 대상이 웹페이지인지 모니터·프로그램 창인지 먼저 정하고, 실제 OS에서 촬영·저장·단축키를 확인해야 합니다.
