1. 폴더와 Markdown의 역할 다시 이해하기

실제로 입력한 질문

프론트 폴더, 문서 폴더 만들어줘 (영문으로) 근데 왜 만드는거야? ㅋ 프로그램만들 때 무조건 시작을 폴더부터 만들긴 하는데..

작업 프로젝트는 1027입니다. frontend에는 화면 코드를, docs에는 기획·설계·사용법을 나눴습니다. 폴더를 먼저 만드는 이유는 앞으로 늘어날 파일의 위치를 정하기 위해서이며, 작은 프로그램은 파일 하나로 시작해도 됩니다.

전날 배운 Markdown을 다시 질문했습니다. Markdown도 제목·강조·목록처럼 글의 구조와 서식을 표시합니다. HTML의 <h1>제목</h1>과 Markdown의 # 제목은 같은 제목을 다른 문법으로 표현합니다. “강조”와 “그냥 메모”의 차이로 이해하면 정확하지 않습니다.

실제로 입력한 질문

당시 공식 안내를 확인해 docs/lotto-645-analysis.md에 규칙·계산식·출처를 정리했습니다. 45개 중 6개를 고르는 조합 수는 C(45,6) = 8,145,060입니다.

4등4개 일치11,115 / 8,145,060
5등3개 일치182,780 / 8,145,060

프로그램 개발 순서는 기능 정의 → 회차 데이터 수집·검증 → 분석 기준 정의 → 계산 기능 → 화면 → 결과 검증으로 정리했습니다. 과거 번호 통계와 다음 추첨의 당첨 예측은 구분해야 합니다.

3. Electron과 Three.js로 3D 추첨 앱 구현

실제로 입력한 질문

파이썬을 사용하지 않고 자바스크립트 혹은 타입스크립트로 처리할 껀데. 필요한 라이브러리는 여기에 맞는 것을 찾아서 정리 후 문서에 추가해줘. 그래픽 처리는 트리.js를 활용해서 3d로 공이 굴러나오면서 실제 로또 번호 추첨처럼 연출을 하도록 문서에 추가해줘.

3D 공이 나오는 효과는 화면 연출이고, 회차 데이터 저장과 분석 계산은 별도 기능입니다. 화려한 화면을 만드는 것과 계산 결과를 검증하는 것을 함께 진행해야 합니다.

4. 설치·빌드·패키징 중 만난 오류

실제로 입력한 질문

권한이나 설정이 안열려서 작업이 진행 안될때는 나한테 말해줘. 터미널에서 따로 실행해야 할 부분은 내가 처리할테니까

npm 연결의 EACCES, Electron 압축 해제와 설치 스크립트 문제를 만났습니다. 사용자 터미널에서 처리해야 하는 경우에는 실행 위치·명령어·성공 확인 방법을 바로 안내하기로 했습니다.

DrawScene.tsx의 Cannot find name drawDuration는 변수 참조 오류여서 코드를 수정했습니다. 수정 뒤 빌드와 테스트 6개가 통과했습니다. 번들 크기 경고와 실제 빌드 실패는 구분했습니다.

패키징 중 app.asar를 바꾸려다 EBUSY가 발생했습니다. 기존 실행 파일과 충돌하지 않도록 매번 생성시각별 새 출력 폴더에 패키징하도록 수정했습니다.

cd C:\Users\User\Desktop\1027\frontend
npm.cmd run package

frontend/시작.cmd도 만들어 최신 패키징 버전을 찾아 실행하도록 했습니다. 시작 파일은 만들어진 앱을 여는 도구이고, 패키징 명령은 변경한 코드를 새 배포 파일로 만드는 작업입니다.

6. Windows 배포 파일 세 가지의 차이

실제로 입력한 질문

빌드를 해서 패키지화를 할껀데 3가지 방식으로 처리해줘. 1. 프로그램 풀러져있는 exe 파일. 2. exe 파일만 있는 (실행화일들이 합쳐져 있는) 파일, 3. 설치화일로 만들어줘.
형태실행 방법전달 방법
폴더형win-unpacked 안의 Lotto Orbit.exe폴더 전체 복사
단일 EXE 포터블Lotto Orbit Portable 1.0.0.exeEXE 하나 복사
설치형Lotto Orbit Setup 1.0.0.exe로 설치설치 파일 전달

이 날 세 가지 파일을 모두 생성했습니다. “앞으로 npm.cmd run package 한 번으로 세 가지를 만든다”는 말은 코드를 수정한 뒤 새 버전을 만들 때의 방법이지, 이미 만들어진 프로그램을 쓰기 전에 다시 실행하라는 뜻은 아닙니다.

SQLite 사용 기능은 앱에 포함되므로 다른 PC에 별도 DB 서버를 설치할 필요는 없습니다. 다만 현재 PC의 번호와 저장 조합은 실행 파일과 별도이므로 데이터도 따로 옮겨야 합니다.

9. 별도 학습: Python 가상환경과 GUI 라이브러리

실제로 입력한 질문

venv 폴더 안에 requirements.txt 화일이 있으면 되는거지?

별도 프로젝트 1027_python에서는 가상환경과 의존성 목록을 학습했습니다. requirements.txt는 venv 밖이면서 프로젝트 폴더 안에 두고, 필요한 라이브러리를 한 줄씩 적습니다. 이 날 프로젝트 루트에 빈 파일을 만들었습니다.

1027_python/
├─ venv/
└─ requirements.txt

.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

라이브러리를 설치하면 기존 가상환경의 Lib/site-packages에 파일이 추가됩니다. requirements.txt가 자동으로 갱신되는 것은 아닙니다. VS Code의 Compact Folders 설정 때문에 경로가 한 줄로 묶여 보일 수 있다는 점도 확인했습니다.

PyQt5와 PySide 계열, Tkinter, wxPython, Kivy, CustomTkinter의 차이를 살펴봤습니다. 색다른 무료 GUI 과제용으로 CustomTkinter를 소개했지만, 이 날 대화에서는 해당 GUI 프로그램을 구현한 기록까지는 없습니다.
