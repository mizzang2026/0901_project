Supabase와 카카오 로그인 연결 완성하기

카카오 OAuth의 두 단계 리디렉션을 이해하고 KOE006 오류 해결 → 운영 배포 → 실제 로그인 진입 확인까지 진행했습니다. Supabase 토큰의 만료와 UTC 시간 표시도 함께 정리했습니다.

1. 카카오 로그인은 두 번 리디렉션된다

카카오에 등록하는 주소와 Supabase에 등록하는 주소는 서로 다릅니다. 로그인 과정에서 카카오가 먼저 Supabase로 돌아오고, Supabase가 다시 우리 웹사이트로 사용자를 보냅니다.

단계이동 방향등록 위치
1차 콜백카카오 → Supabase카카오 Developers의 REST API 키 설정
2차 콜백Supabase → 웹사이트의 /auth/callbackSupabase Authentication URL Configuration

전체 로그인 흐름은 다음과 같습니다.

운영 사이트 → Supabase OAuth → 카카오 로그인·동의 → Supabase callback → 운영 사이트 callback → 프로필

2. 카카오와 Supabase의 필수 설정

  1. 카카오 로그인 활성화 — 카카오 Developers의 카카오 로그인 일반 설정을 ON으로 바꾼다.
  2. REST API 키 사용 — JavaScript 키가 아니라 Supabase에 등록한 REST API 키를 사용한다.
  3. Client Secret 확인 — REST API 키에 연결된 Client Secret을 활성화하고 Supabase 값과 일치시킨다.
  4. 카카오 Redirect URI — https://PROJECT_REF.supabase.co/auth/v1/callback을 등록한다.
  5. Supabase Site URL — 실제 Vercel 운영 사이트의 origin을 등록한다.
  6. Supabase Redirect URLs — 운영 사이트의 /auth/callback과 필요한 로컬 개발 주소를 허용한다.
  7. 동의항목 — 닉네임, 프로필 이미지, 사용할 경우 이메일 동의항목을 설정한다.

이메일을 받지 않을 때: 카카오 앱에서 이메일 동의 권한을 사용할 수 없다면 Supabase Kakao Provider의 Allow users without an email을 활성화합니다.

3. KOE006은 Redirect URI 불일치 오류다

KOE006은 카카오 로그인 요청에 포함된 redirect_uri가 카카오 Developers에 등록된 값과 정확히 같지 않을 때 발생합니다.

점검 항목확인할 내용
키 종류Redirect URI를 JavaScript 키가 아닌 REST API 키에 등록했는가?
프로젝트Supabase Provider의 Client ID와 같은 카카오 앱·키를 수정했는가?
프로토콜http와 https가 정확히 일치하는가?
경로/auth/v1/callback 철자와 슬래시가 정확한가?
마지막 슬래시등록값과 요청값 중 한쪽에만 불필요한 /가 붙지 않았는가?
브라우저 상태수정 후 기존 탭을 닫고 시크릿 창에서 새 요청으로 시험했는가?

오류 문구만 보지 않고 Supabase의 /auth/v1/authorize 응답에 있는 Location 헤더를 확인하면 실제 client_id와 redirect_uri를 정확히 찾을 수 있습니다.

4. GitHub, Vercel, Supabase 반영 확인

  1. 로컬 검증 — lint와 production build가 성공하는지 확인한다.
  2. GitHub — 변경 커밋을 main 브랜치에 push하고 원격 상태를 확인한다.
  3. Vercel — Production 배포가 READY인지, 운영 도메인이 새 배포에 연결됐는지 확인한다.
  4. 운영 번들 — 배포된 JavaScript에 카카오 로그인과 callback 코드가 실제 포함됐는지 확인한다.
  5. Supabase — Edge Function의 health 응답과 DB 연결 상태를 확인한다.
  6. OAuth 진입 — 운영 주소에서 카카오 계정 로그인 화면까지 정상 도달하는지 확인한다.

주의: 배포 명령이 성공했다는 메시지만으로 끝내지 않습니다. 운영 도메인의 HTML과 번들 해시, 실제 API 응답을 다시 조회해야 캐시나 잘못된 Root Directory 문제를 찾을 수 있습니다.

5. Supabase 토큰은 용도와 만료를 구분한다

종류역할만료 영향
Personal Access TokenCLI, Management API, 자동 배포만료되면 이후 관리·배포 명령이 실패
브라우저용 공개 키클라이언트의 제한된 Supabase 접근PAT와 별개이며 RLS로 보호
Service Role Key서버의 관리자 권한 작업프런트와 GitHub에 절대 공개하지 않음

기존 Personal Access Token의 만료일은 늘릴 수 없습니다. 만료 전에 새 Scoped Token을 만들고 정상 동작을 확인한 뒤 기존 토큰을 폐기합니다.

  • 범위 제한 — 필요한 프로젝트 하나만 선택
  • 최소 권한 — DB, Migration, Edge Function 등 작업에 필요한 권한만 부여
  • 안전한 교체 — 새 토큰을 먼저 시험한 뒤 기존 토큰 삭제
  • 비밀 유지 — 채팅, 소스 코드, 커밋, 터미널 출력에 토큰을 남기지 않음

관리용 PAT가 만료돼도 이미 배포된 사이트와 카카오 로그인이 즉시 중단되는 것은 아닙니다. 다음 CLI 배포나 관리 작업을 하기 전에 새 토큰으로 교체하면 됩니다.

6. Supabase의 +00 시간은 UTC다

2026-10-12 05:42:26.020952+00에서 +00은 세계 표준시 UTC를 뜻합니다. 특정 미국 지역 시간이 아니라 전 세계 시스템이 함께 사용하는 기준 시간입니다.

표시뜻예시
UTC세계 표준시, UTC+0오전 5시 42분
한국 표준시UTC+9같은 순간 오후 2시 42분

DB에는 UTC로 저장하고 사용자 화면에서 한국 시간으로 변환하는 방식이 안전합니다.

new Date(created_at).toLocaleString('ko-KR', {
  timeZone: 'Asia/Seoul',
})

SQL에서 한국 시간으로 확인할 때는 다음처럼 변환할 수 있습니다.

select created_at at time zone 'Asia/Seoul'
from 테이블명;

오늘의 핵심 흐름

카카오 REST API 키 확인 → Supabase callback 등록 → 앱 callback 허용 → KOE006 실제 요청값 확인 → GitHub push → Vercel 운영 배포 → Supabase·OAuth 검증

OAuth 문제는 주소 하나만 보는 것이 아니라 어떤 서비스가 누구에게 돌아오는 주소인지 구분해야 해결할 수 있습니다. 배포 후에는 명령 결과와 함께 실제 운영 화면과 네트워크 흐름까지 확인합니다.
