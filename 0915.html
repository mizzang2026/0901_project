02

Vite로 React 설정

이 작업은 터미널 명령을 하나씩 직접 입력한 것이 아니라, 먼저 Codex에게 아래와 같이 자연어로 요청하면서 시작했습니다.

0915 페이지에서 프론트 폴더, 백엔드 폴더, 문서 폴더 만들어줘.
프론트 폴더 안에 리액트를 설치해주는데, 비트를 활용해서 리액트를 셋팅해줘.

내가 직접 입력한 것은 위 요청문입니다. 아래의 npm create vite, npm install 같은 명령은 요청을 처리하기 위해 Codex가 터미널에서 자동으로 실행한 명령입니다. 여기서 요청문의 ‘비트’는 React 개발 도구인 Vite를 뜻합니다.

Vite는 빠른 개발 서버와 최적화된 빌드 기능을 제공하는 도구입니다. React 프로젝트를 간단하게 시작할 수 있고, 필요한 패키지를 프로젝트별로 설치해 독립적으로 관리할 수 있습니다.

npm create vite@latest frontend -- --template reactReact 템플릿으로 frontend 프로젝트 생성
cd frontend프론트엔드 폴더로 이동
npm installpackage.json에 기록된 패키지를 node_modules에 설치
npm run devReact 개발 서버 실행
package.json 확인→npm install→node_modules 생성→npm run dev

터미널에 표시된 http://localhost:5173/ 주소에서 React 화면이 보이면 개발 서버가 정상적으로 실행된 것입니다. node_modules는 용량이 크므로 Git에 올리지 않고, package.json을 이용해 각자 다시 설치합니다.

04

Node.js와 Express 백엔드 구성

백엔드도 터미널 명령을 하나씩 직접 입력한 것이 아니라, Codex에게 아래와 같이 자연어로 요청해 구성했습니다.

백엔드 폴더 안에 백엔드 서버를 만들 건데,
노드 익스프레스를 활용해서 백엔드 서버를 구성해줘.

내가 직접 입력한 것은 위 요청문입니다. 아래의 npm init -y, npm install express, node server.js 같은 명령은 요청을 처리하기 위해 Codex가 터미널에서 자동으로 실행한 명령입니다. 요청문의 ‘노드 익스프레스’는 Node.js에서 사용하는 Express를 뜻합니다.

새 터미널에서 backend 폴더로 이동한 뒤 Node.js 프로젝트를 만들고 Express를 설치합니다. Express는 브라우저나 프론트엔드에서 보낸 요청을 받아 응답하는 백엔드 서버를 간결하게 구성할 수 있게 해 줍니다.

Node.js의 의미

자바스크립트를 브라우저 밖에서도 실행할 수 있게 해 주는 실행 환경입니다. 이번 프로젝트에서는 백엔드의 server.js 파일을 실행하고 서버 프로그램이 계속 동작하도록 하는 기반으로 사용했습니다.

Express의 의미

Node.js에서 웹 서버와 API를 더 간단하게 만들도록 도와주는 프레임워크입니다. 이번 프로젝트에서는 주소별 요청을 받고, 필요한 작업을 처리한 뒤 프론트엔드에 응답을 보내는 역할로 적용했습니다.

쉽게 구분하면 Node.js는 백엔드 서버를 움직이는 실행 환경이고, Express는 그 환경 위에서 요청과 응답을 편리하게 구성하는 도구입니다. 따라서 ‘노드 익스프레스’는 하나의 프로그램 이름이 아니라 Node.js 환경에서 Express를 사용해 백엔드 서버를 만든 구성을 의미합니다.

npm init -y기본 설정으로 package.json 생성
npm install expressExpress 패키지 설치
node server.js작성한 백엔드 서버 실행
Reactlocalhost:5173
→ 요청
Expresslocalhost:3000
→ 처리
데이터응답 반환

백엔드 주소는 http://localhost:3000입니다. 아직 화면을 제공하는 경로를 만들지 않았다면 브라우저에서 별도 페이지가 보이지 않아도 됩니다. 서버가 실행 중이고 요청에 응답하는지를 확인하는 것이 중요합니다.

05

게시판 프론트엔드 페이지 구성

React의 각 화면을 페이지 컴포넌트로 나누고 주소에 따라 필요한 화면이 나타나도록 구성합니다. 공통 내비게이션은 재사용하되 로그인 여부에 따라 사용할 수 있는 메뉴를 구분합니다.

1. 메인 페이지서비스 소개와 최신 게시글 표시
2. 로그인 페이지이메일과 비밀번호로 사용자 인증
3. 회원가입 페이지새 사용자 정보 입력과 계정 생성
4. 프로필 페이지로그인한 사용자의 정보와 작성 글 확인
5. 게시판 페이지전체 게시글 목록과 검색·분류 제공
6. 게시글 생성 페이지제목과 본문을 입력해 새 글 저장
7. 게시물 상세 페이지선택한 글의 내용과 작성자 정보 표시
frontend/src/pages/
├─ HomePage.jsx
├─ LoginPage.jsx
├─ SignupPage.jsx
├─ ProfilePage.jsx
├─ BoardPage.jsx
├─ PostCreatePage.jsx
└─ PostDetailPage.jsx

페이지 이동은 React Router로 연결할 수 있습니다. 프로필과 글쓰기처럼 인증이 필요한 주소는 화면에서만 숨기지 말고 보호된 라우트와 백엔드 인증을 함께 적용합니다.

06

SQLite 데이터베이스와 환경 변수

backend 폴더에 SQLite 데이터베이스를 연결해 사용자와 게시글을 저장합니다. 서버 주소, 토큰 비밀키, 관리자 계정처럼 실행 환경마다 달라지거나 공개하면 안 되는 값은 .env에서 관리합니다.

users 테이블

사용자 ID, 이름, 이메일, 암호화된 비밀번호, 권한을 저장합니다.

posts 테이블

게시글 ID, 작성자 ID, 제목, 본문, 작성·수정일을 저장합니다.

npm install better-sqlite3 dotenvSQLite 연결과 환경 변수 사용 패키지 설치
require('dotenv').config()서버가 시작될 때 .env 값 불러오기
PORT=3000
DATABASE_PATH=./data/board.db
JWT_SECRET=충분히_길고_무작위인_비밀키
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD_HASH=해시된_관리자_비밀번호

.env는 Git에 올리지 않습니다. 실제 비밀번호 대신 단방향 해시를 저장하고, 공유용 파일에는 키 이름만 담은 .env.example을 제공합니다. 관리자 계정도 서버 시작 시 안전하게 생성하거나 별도의 초기화 스크립트로 등록합니다.

08

로그인 상태에 따른 내비게이션

메인 페이지의 프로필 버튼은 모든 방문자에게 항상 표시하지 않고, 로그인 상태를 확인한 뒤에만 보여 줍니다. 로그아웃 상태에서는 로그인과 회원가입 메뉴를 제공하고, 로그인 상태에서는 프로필과 로그아웃 메뉴로 전환합니다.

세션 확인→사용자 인증→메뉴 전환→보호된 페이지 접근

로그아웃 상태

로그인 · 회원가입을 표시하고 프로필 버튼은 숨깁니다.

로그인 상태

프로필 · 로그아웃을 표시하고 사용자 전용 기능을 활성화합니다.

새로고침 직후 프로필 버튼이 잠깐 보이는 현상을 막으려면 인증 확인 전에는 메뉴를 숨겨 두고, 세션 확인이 끝난 뒤 알맞은 메뉴만 렌더링합니다.

09

관리자 계정 정보 변경과 인증 용어

관리자가 자신의 이메일과 비밀번호를 바꿀 수 있도록 관리자 화면에 계정 설정 메뉴를 추가합니다. 현재 비밀번호를 먼저 확인한 뒤 새 이메일이나 새 비밀번호를 저장하고, 변경된 비밀번호는 원문이 아닌 해시 값으로 데이터베이스에 보관합니다.

현재 비밀번호 확인→새 정보 입력→비밀번호 해시 생성→DB 저장·재로그인
  • 해시 Hash비밀번호를 원래 내용으로 되돌리기 어려운 값으로 변환하는 것
  • 세션 Session로그인한 사용자인지 서버가 일정 시간 기억하는 로그인 상태
  • 시크릿 Secret로그인 토큰의 위조 여부를 확인할 때 서버만 사용하는 비밀키

    • 처음 관리자 만들기

    .env의 초기 관리자 이메일과 비밀번호로 서버가 최초 계정을 생성합니다. 생성 후에는 초기 비밀번호 항목을 제거하는 것이 안전합니다.

    나중에 정보 변경하기

    관리자 대시보드의 계정 설정에서 이메일과 비밀번호를 변경합니다. 서버는 현재 비밀번호와 관리자 권한을 확인한 뒤 저장합니다.

    # 최초 관리자 계정 생성에만 사용하는 .env 예시
    ADMIN_EMAIL=내가_사용할_이메일
    ADMIN_INITIAL_PASSWORD=내가_정한_초기_비밀번호
    JWT_SECRET=충분히_길고_무작위인_서버_비밀키

    쉽게 구분하기: 비밀번호는 사용자가 입력하고, 해시는 데이터베이스에 저장합니다. 세션은 로그인 상태를 기억하며, 시크릿은 서버가 세션이나 토큰을 안전하게 확인할 때 사용합니다. 시크릿은 관리자 비밀번호가 아니며 사용자에게 보여 주지 않습니다.

    • 관리자 이메일 변경
    • 관리자 비밀번호 변경
    • 현재 비밀번호 재확인
    • 변경 후 기존 세션 종료

    권장 방식: .env는 최초 관리자 생성용으로만 사용하고, 이후 계정 변경은 관리자 전용 계정 설정 화면에서 처리합니다. 비밀번호와 시크릿은 GitHub나 프론트엔드 코드에 올리지 않습니다.
