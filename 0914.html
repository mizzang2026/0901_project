블로그 핵심 기능 구현과
사용자 경험 개선

프로필과 게시글 기능을 실제 데이터에 연결하고, 화면에 남아 있는 더미 데이터를 제거합니다. 로그인 흐름과 페이지 로딩 속도까지 점검하며 블로그를 한 단계 더 완성합니다.

ProfileCRUDAuthenticationPerformance
01

프로필 페이지 구현

로그인한 사용자의 정보를 불러와 프로필 페이지에 표시하고, 필요한 정보는 직접 변경할 수 있도록 구성합니다. 화면에 고정된 예시 값 대신 사용자별 데이터를 보여주는 것이 핵심입니다.

기본 정보이름과 이메일 등 계정 정보 표시
활동 정보작성한 게시글과 사용자 활동 연결
수정 기능변경한 프로필을 저장하고 화면에 즉시 반영

프로필 정보는 현재 로그인한 사용자에게만 연결되어야 하며, 다른 사용자의 데이터와 섞이지 않도록 사용자 식별값을 기준으로 조회합니다.

02

블로그 작성·수정 기능 구현

글 작성 화면에서 입력한 제목과 내용을 저장하고 게시글 목록과 상세 화면에 반영합니다. 작성자는 기존 글을 다시 불러와 수정한 뒤 변경 내용을 저장할 수 있어야 합니다.

내용 입력→유효성 검사→데이터 저장→목록·상세 반영

글 작성

제목과 본문을 검사한 뒤 작성자, 작성일과 함께 새 게시글로 저장합니다.

글 수정

게시글 ID로 기존 데이터를 불러오고 작성자 권한을 확인한 뒤 변경 내용을 저장합니다.

CRUD는 데이터의 생성(Create), 조회(Read), 수정(Update), 삭제(Delete)를 뜻합니다. 이번 수업에서는 작성과 수정 흐름을 중심으로 블로그의 핵심 데이터 처리를 구현합니다.

03

더미 데이터와 하드코딩 제거

화면 확인을 위해 HTML이나 JavaScript에 직접 넣어 둔 사용자와 게시글 예시 데이터를 제거합니다. 실제 저장소에서 받은 결과를 기준으로 화면을 만들고, 데이터가 없을 때의 빈 화면도 준비합니다.

  1. 페이지에 직접 작성된 예시 사용자와 게시글을 찾습니다.
  2. 고정된 값 대신 데이터 조회 결과를 화면에 출력합니다.
  3. 데이터가 없거나 요청에 실패한 경우 안내 문구를 표시합니다.
  4. 로딩 중, 성공, 빈 결과, 오류 상태가 각각 자연스럽게 보이는지 확인합니다.

하드코딩을 없애면 데이터가 바뀔 때 HTML을 매번 수정하지 않아도 되고, 모든 사용자가 자신의 최신 정보를 볼 수 있습니다.

04

로그인과 페이지 속도 개선

로그인 여부를 더 안정적으로 확인하고, 인증이 필요한 페이지의 접근 흐름을 정리합니다. 동시에 불필요한 요청과 중복 렌더링을 줄여 사용자가 페이지를 더 빠르게 볼 수 있도록 개선합니다.

로그인 개선

세션 확인, 만료 처리, 로그인 후 이동, 로그아웃 상태의 접근 제한을 점검합니다.

속도 개선

필요한 데이터만 요청하고 스크립트 실행 시점과 이미지·파일 크기를 점검합니다.

  • 중복 API 요청 줄이기
  • 로딩 상태 명확히 표시하기
  • 인증 결과 재사용하기
  • 불필요한 화면 갱신 줄이기
