LEARNING LOG · DAY 07 · 2026.09.21

하드코딩을 걷어내고
실제 데이터로 연결하기

로그인한 사용자의 프로필과 게시판을 데이터베이스에 연결하고, 내비게이션을 정리합니다. 일반 회원과 분리된 관리자 계정은 환경 변수로 안전하게 초기화합니다.

AuthenticationDatabaseBoardAdmin.env
01

로그인 정보와 프로필 연결

프로필 페이지에 직접 입력해 둔 이름과 이메일을 제거하고, 현재 로그인한 사용자의 정보를 백엔드에서 조회해 표시하도록 변경합니다. 회원가입과 로그인으로 받은 사용자 정보는 데이터베이스에 저장하고, 인증된 사용자 ID를 기준으로 자신의 프로필만 불러옵니다.

로그인 요청→DB 사용자 확인→인증 정보 발급→내 프로필 조회

데이터 저장

이름, 이메일, 해시된 비밀번호와 권한을 사용자 테이블에 저장합니다.

프로필 표시

고정된 예시 값이 아니라 로그인 세션이나 토큰으로 확인한 사용자 정보를 표시합니다.

프론트엔드에서 전달한 사용자 ID를 그대로 믿지 않고, 서버가 검증한 로그인 정보에서 사용자 ID를 가져와야 다른 사람의 정보에 접근하는 문제를 막을 수 있습니다.

02

내비게이션 정보 정리

전체 내비게이션을 점검하고 요청한 프로필 페이지 버튼을 삭제합니다. 메뉴에서 버튼을 없애는 작업과 별개로, 더 이상 사용하지 않는 프로필 경로가 있다면 라우팅과 연결 코드도 함께 정리합니다.

메뉴 확인PC와 모바일 내비게이션의 중복 링크 점검
프로필 제거공통 내비게이션에서 프로필 버튼 삭제
인증 메뉴로그인 상태에 맞는 메뉴만 표시

화면의 버튼만 지워도 주소를 직접 입력하면 페이지에 접근할 수 있습니다. 프로필 페이지 자체를 사용하지 않는다면 해당 라우트의 유지 여부도 함께 결정해야 합니다.

03

게시판을 실제 데이터베이스에 연결

게시판 화면에 하드코딩된 게시글과 작성자 예시를 모두 제거합니다. 게시글 목록·상세·작성·수정·삭제가 백엔드 API를 거쳐 데이터베이스의 실제 데이터를 사용하도록 연결합니다.

화면 요청→게시판 API→DB 조회·저장→최신 화면 반영

조회

데이터베이스에서 게시글 목록과 상세 내용을 가져오고 빈 결과와 오류 상태도 표시합니다.

변경

로그인한 작성자만 글을 작성하고 자신의 글을 수정하거나 삭제할 수 있게 서버에서 권한을 확인합니다.

게시판의 하드코딩된 예시 데이터를 모두 제거하고,
게시글 CRUD를 백엔드 API와 데이터베이스에 연결해줘.
작성·수정·삭제 시 서버에서 로그인 사용자와 작성자 권한도 확인해줘.

“하드코딩을 제거해 달라”는 말만으로도 방향은 전달되지만, 위처럼 데이터베이스 연동 범위와 권한 확인까지 명시하면 원하는 결과를 더 정확하게 요청할 수 있습니다.

04

.env로 관리자 계정 초기화

관리자는 일반 회원가입 화면에서 만들지 않습니다. 내가 .env에 입력한 초기 관리자 이메일과 비밀번호를 서버가 읽고, 일치하는 관리자 계정이 데이터베이스에 없을 때 별도의 관리자 계정을 생성하거나 초기화하도록 구성합니다.

# 실제 값은 직접 입력하고 Git에 올리지 않습니다.
ADMIN_EMAIL=내가_사용할_관리자_이메일
ADMIN_INITIAL_PASSWORD=내가_정한_초기_비밀번호
.env 불러오기→관리자 계정 조회→비밀번호 해시→DB 생성·확인

계정이 없는 경우

.env 값을 검사한 뒤 비밀번호를 서버 내부에서 해시하고 관리자 권한으로 DB에 저장합니다.

정보가 다른 경우

기존 계정을 무조건 덮어쓰지 않고 충돌을 기록합니다. 명시적인 초기화나 변경 절차를 통해서만 관리자 정보를 갱신합니다.

  • 관리자 회원가입 경로 차단
  • 서버 시작 시 필수 환경 변수 검사
  • 비밀번호 원문을 로그나 DB에 저장하지 않기
  • 관리자 전용 API에서 로그인과 권한 모두 확인

.env는 관리자 계정의 최초 생성 정보로 사용하고 저장소에는 올리지 않습니다. 비밀번호 해시는 애플리케이션이 내부에서 처리하며, 데이터베이스에는 원문 대신 해시 값만 저장합니다.
