개인 블로그 재구성과
DB 연동 준비

GitHub Pages와 Google 스프레드시트를 열고 데이터 연동을 준비하면서, 기존 개인 프로필 사이트를 게시글 중심의 블로그 구조로 변경했습니다.

BlogGoogle SheetsDBCodex
01

Google Sheets를 DB처럼 사용하기

GitHub Pages는 정적 웹사이트이므로 자체적으로 데이터를 저장할 서버가 없습니다. 수업에서는 Google 스프레드시트를 간단한 데이터 저장소처럼 사용하고 Google Apps Script를 연결 통로로 활용할 예정입니다.

웹페이지 입력→Apps Script→Google Sheets 저장→웹페이지 조회
02

블로그 기본 화면 추가

앞으로 데이터 연동에 사용할 회원가입, 로그인, 프로필, 게시글 목록, 게시글 상세, 게시글 작성 화면을 먼저 구성했습니다.

현재는 화면 구조를 만든 단계입니다. 실제 저장과 로그인 처리는 Google Sheets 및 Apps Script 연동 후 구현합니다.

03

Google 스프레드시트와 Apps Script 준비

웹사이트에서 사용할 데이터를 저장하기 위해 Google 스프레드시트를 새로 만들고, 용도를 알아보기 쉽도록 문서 이름을 변경했습니다.

  1. Google 스프레드시트를 새로 생성합니다.
  2. 왼쪽 위의 문서 제목을 눌러 스프레드시트 이름을 변경합니다.
  3. 상단 메뉴에서 확장 프로그램 → Apps Script를 선택합니다.
  4. 열린 Apps Script 편집기에서 웹페이지와 스프레드시트를 연결할 코드를 작성할 준비를 합니다.

Google Apps Script는 웹페이지에서 받은 데이터를 스프레드시트에 저장하거나, 저장된 데이터를 다시 웹페이지로 전달하는 중간 연결 역할을 합니다.

04

Google 스프레드시트 ID 확인

Apps Script에서 특정 스프레드시트를 지정하려면 문서 URL에 포함된 고유 ID를 확인합니다.

https://docs.google.com/spreadsheets/d/스프레드시트_ID/edit

URL에서 /d/와 /edit 사이의 문자열이 스프레드시트 ID입니다. Apps Script에서는 다음과 같이 사용할 수 있습니다.

const spreadsheet = SpreadsheetApp.openById('스프레드시트_ID');

보안 주의: 실제 ID나 배포 주소 같은 특정 키 값은 학습기록, 공개 GitHub 저장소, 화면 캡처에 그대로 남기지 않습니다. 스프레드시트 공유 권한도 필요한 범위로 제한하고, 비밀번호·인증 토큰 같은 민감한 정보는 시트에 저장하지 않습니다.

05

Apps Script를 웹 앱으로 공개하기

GitHub Pages에서 Apps Script로 회원가입과 로그인 요청을 보낼 수 있도록 스크립트를 웹 앱 형태로 배포합니다.

  1. Apps Script 오른쪽 위의 배포 → 새 배포를 선택합니다.
  2. 배포 유형에서 웹 앱을 선택합니다.
  3. 실행 사용자를 나로 설정합니다.
  4. 액세스 권한을 모든 사용자로 설정합니다.
  5. 배포를 누른 뒤 액세스 승인을 선택합니다.
  6. 사용할 Google 계정을 선택합니다.
  7. Google의 확인되지 않은 앱 안내가 나오면 고급을 누릅니다.
  8. 본인이 만든 프로젝트가 맞는지 이름을 확인하고 Go to DB(안전하지 않음)를 선택합니다.
  9. 요청하는 권한을 확인한 뒤 허용을 누릅니다.
  10. 배포가 완료되면 발급된 웹 앱 URL을 확인합니다.

승인 화면 주의: Go to DB는 현재 직접 만든 Apps Script 프로젝트 이름이 DB이기 때문에 선택한 항목입니다. 출처를 모르는 다른 앱에서 같은 경고가 나오면 진행하지 않습니다.

공개 범위 주의: 모든 사용자 설정은 스프레드시트 문서 자체를 공개한다는 뜻이 아니라, 웹 앱 주소로 누구나 요청을 보낼 수 있게 한다는 뜻입니다. 따라서 서버 코드에서 입력값 검사와 접근 권한 처리가 필요하며 실제 배포 URL은 공개 학습기록에 적지 않습니다.

06

첫 번째 웹 앱 배포와 회원 기능 연결

Apps Script의 액세스 권한을 승인하고 버전 1 웹 앱 배포를 완료했습니다. 발급된 /exec 주소를 블로그의 회원가입·로그인 폼 JavaScript에 연결했습니다.

가입·로그인 입력→웹 앱 URL 요청→Apps Script 처리→결과 표시

배포 ID와 실제 웹 앱 URL은 학습기록 본문에 적지 않습니다. 브라우저에서 호출하는 웹 앱 주소는 개발자 도구에서 확인될 수 있으므로, 보안은 주소를 숨기는 방식이 아니라 서버의 입력 검증과 권한 처리로 구성해야 합니다.

07

배포된 웹 앱 연결 테스트

배포된 웹 앱 URL에 GET 요청을 보내 Apps Script 연결이 정상입니다라는 응답을 확인했습니다. 잘못된 회원가입 정보도 서버에서 거부하여 입력 검사가 동작하는 것을 확인했습니다.

정상 확인

기본 연결 응답과 회원가입의 이름·이메일·비밀번호 검증이 정상적으로 실행되었습니다.

추가 확인

존재하지 않는 계정의 로그인 테스트에서 서버 오류가 반환되어 Users와 Sessions 시트 생성 여부를 확인해야 합니다.

  1. Apps Script 편집기에서 함수 목록의 setup을 선택합니다.
  2. 실행을 누르고 필요한 권한을 승인합니다.
  3. 스프레드시트 아래쪽에 Users와 Sessions 탭이 만들어졌는지 확인합니다.
  4. 필요하면 새 버전으로 웹 앱을 다시 배포한 뒤 회원가입과 로그인을 재시험합니다.
08

회원가입 405 오류 해결

GitHub Pages의 회원가입 버튼을 눌렀을 때 화면이 바뀌며 405 Not Allowed가 나타났습니다. 정적 호스팅인 GitHub Pages는 폼의 POST 요청을 직접 처리할 수 없는데, JavaScript가 실행되지 않은 상태에서 폼이 현재 페이지로 제출된 것이 원인이었습니다.

  1. 회원가입과 로그인 폼의 기본 action을 Apps Script 웹 앱 주소로 지정합니다.
  2. 요청 종류를 구분하도록 숨김 입력값 action=signup 또는 action=login을 추가합니다.
  3. JavaScript 파일 주소에 버전 값을 붙여 브라우저가 최신 연결 코드를 다시 내려받게 합니다.

JavaScript가 정상 실행되면 화면을 이동하지 않고 결과 메시지를 표시합니다. JavaScript를 불러오지 못하더라도 폼이 GitHub Pages가 아닌 Apps Script로 전송되어 405 오류를 피할 수 있습니다.
